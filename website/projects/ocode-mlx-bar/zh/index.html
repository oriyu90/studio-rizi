设计约定

只增加 Provider，不重写其他功能。

差异越小，越容易验证质量。未选择 MLXBar 时，目标是保持与 OpenCode v1.18.30 相同的可观察行为。

01 / UPSTREAM

保留现有行为

未改动界面、快捷键、智能体、提示词、工具、MCP、权限、会话与重试。

02 / LIMITS

原生自动压缩

把 MLXBar 的有效上下文与安全输入上限交给 OpenCode 原有模型metadata和压缩策略。

03 / FAILURE

MLXBar 离线也能启动

模型发现短暂且有界，服务器离线不会拖垮 OCode 或其他 Provider。

Provider

直接出现在 OpenCode 原有模型列表。

没有专用向导，也没有另一套界面。启动 MLXBar 后，从原有 Provider 与模型选择器使用即可。

动态发现模型

启动时通过 GET /v1/models 读取当前模型清单。

流式聊天

沿用 OpenAI-compatible SDK 通路处理流式回复与工具调用。

本机或局域网

可用默认localhost，也可在普通Provider设置中填写LAN地址与token。

不猜测能力

视觉、推理与token上限只取明确metadata，不从模型名称推断。

开始使用

启动 MLXBar，然后选择模型。

默认本机配置无需额外设置。只有token认证或LAN连接才需使用OpenCode普通Provider设置。

  1. 启动 MLXBar加载模型并启用 OpenAI 兼容 API。
  2. 打开 OCode mlx-bar启动时会短暂探测 /v1/models。
  3. 选择 MLXBar 模型在原有模型选择器中选择 mlxbar/<model>。
{
  "provider": {
    "mlxbar": {
      "options": {
        "baseURL": "http://127.0.0.1:11435/v1",
        "apiKey": "YOUR_MLXBAR_TOKEN"
      }
    }
  }
}

范围带来的安全

有边界、相隔离、只认明示。

即使是本地Provider，主机内存压力与上下文溢出仍是两种不同情况。

保留含义不明的内存压力

只有MLXBar明确标记可通过上下文恢复时，才转成标准上下文溢出。

不虚构上限

缺少安全输入上限时，不以百分比heuristic代替。

内存边界

模型发现响应限制为4 MiB与10,000个模型。

不记录秘密

适配层不记录API key、Authorization header、提示词或工具结果。
