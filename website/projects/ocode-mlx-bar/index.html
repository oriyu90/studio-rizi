Design contract

足したのは、Providerだけ。

改造範囲を小さく保つことを品質基準にしています。MLXBarを選ばない限り、OpenCode v1.18.30と同じ挙動を目指します。

01 / UPSTREAM

既存機能を維持

UI、キーバインド、Agent、Prompt、Tool、MCP、Permission、Session、Retryを変更していません。

02 / LIMITS

標準Auto Compact

MLXBarの実効contextと安全入力上限を既存model metadataへ渡し、OpenCode標準の圧縮判定へ任せます。

03 / FAILURE

停止中でも起動

モデル検出は短時間・容量制限付き。MLXBarが停止中でもOCode全体や他Providerを巻き込みません。

Provider

OpenCodeの選択画面に、そのまま現れる。

専用wizardや独自画面はありません。MLXBarを起動すると、既存のProvider・モデル選択から利用できます。

動的モデル検出

GET /v1/models から現在のmodel inventoryを起動時に取得します。

Streaming Chat Completions

既存のOpenAI-compatible SDK経路で、stream応答とtool callingを扱います。

Local / LAN

既定のlocalhostに加え、既存Provider設定でLANのbase URLとtokenを指定できます。

能力を推測しない

画像・reasoning・token limitは明示metadataだけを使用。モデル名から推測しません。

Get started

MLXBarを起動したら、選ぶだけ。

既定構成なら追加設定は不要です。token認証やLAN利用時だけ、OpenCodeの通常Provider設定を使います。

  1. MLXBarを起動モデルを読み込み、OpenAI互換APIを有効にします。
  2. OCode mlx-barを開く起動時に /v1/models を短時間probeします。
  3. MLXBarモデルを選択既存のモデル選択画面から mlxbar/<model> を選びます。
{
  "provider": {
    "mlxbar": {
      "options": {
        "baseURL": "http://127.0.0.1:11435/v1",
        "apiKey": "YOUR_MLXBAR_TOKEN"
      }
    }
  }
}

Safety by scope

推測せず、壊さず、閉じ込める。

local providerだからこそ、host memoryとcontext overflowを混同しません。

曖昧なMEMORY_PRESSUREを保持

context回復可能と明示された場合だけ、標準context overflowへ変換します。

上限を捏造しない

安全入力上限がない場合、70%などの独自heuristicは作りません。

メモリ境界

discovery応答は4 MiB、最大10,000モデルに制限します。

秘密を記録しない

API key、Authorization header、prompt、tool resultをMLXBar adapterからlogしません。
