WHY GLINTVNC

VNC に必要なのは、
速さと安心。

画面が重い、接続が不安、設定が難しい。GlintVNC はこの 3 つを減らすことから始めました。

01

差分だけを描く

画面全体を毎回送らず、変わった矩形だけを受け取って GPU に転送します。ウィンドウを動かしても、引っぱられる感覚が出にくい設計です。

02

壊れたデータでも落ちない

リモートの画像はすべて外部入力として検証します。サイズ、展開後のバイト数、メモリ上限を確認し、15 秒応答がなければ接続を切ります。

03

日本語で、最後まで

接続一覧、プロファイル、設定、セッション操作バーまで日英対応。パスワードは macOS の Keychain にだけ保存します。

WHAT IT DOES

毎日の操作を、
そのまま遠くへ。

遠隔作業でよく使う機能を、余計な手順なしで。接続ごとに設定が残るので、次回からは一覧で選ぶだけです。

接続のしかたを見る →
01複数のホストを、同時に
接続ごとに独立したウィンドウが開きます。2 台の Mac を並べて作業することもできます。
02全画面に、集中
F8 で操作バーを表示・非表示、Esc で全画面を終了。マウスを画面上端へ近づけるとバーが現れます。
03表示を、合わせる
全体表示（Fit）、原寸（1:1）、拡大（Stretch）を接続ごとに保存。キーマップもプロファイル単位で選べます。
04コピー＆ペーストを、そのまま
テキストのクリップボードを双方向に同期できます。設定でいつでもオフにできます。
05残像を、すぐ消す
⌘R または操作バーの「再描画」で画面全体を描き直します。表示が古いと感じたときの即効策です。
06パスワードを、安全に
保存先は macOS の Keychain のみ。設定 JSON、ログ、コマンドライン引数には残しません。

  • ポート通常は 5900
  • パスワードmacOS Keychain に保存（プロファイル保存時に登録）

SAFETY

画面データは、
信頼できない入力。

VNC サーバーから届くピクセルや矩形が、常に正しいとは限りません。GlintVNC はデコードの前後にサイズと上限を確認し、固まった接続がアプリ全体を止めないようにします。

  • ✓
    すべて safe Rust

    コアには #![forbid(unsafe_code)] を適用しています。

  • ✓
    境界チェック

    Raw、CopyRect、ZRLE の各デコーダで、寸法と転送先を検査します。

  • ✓
    メモリ上限

    1 更新あたり RGBA 128 MiB、画面は 16 Mpx までに制限します。

  • ✓
    確実な解放

    切断やフォーカス喪失時に、押されたキーとマウスボタンを解放します。

  • ✓
    Keychain のみ

    認証情報を設定ファイルやログへ書きません。

標準の VNC は通信を暗号化しません。インターネットへ直接公開せず、信頼できる LAN か VPN の中で使ってください。TLS / VeNCrypt と Apple の ARD 認証は現バージョンでは未対応です。

初回起動の手順

  1. ダウンロードした DMG を開き、GlintVNC を Applications へドラッグします。

FAQ

よくある質問

導入前に迷いやすい点をまとめました。

Apple Silicon の Mac でも使えますか？

現バージョンは Intel x86_64 のみを対象とし、Apple Silicon では未検証です。

パスワードはどこに保存されますか？

macOS の Keychain だけに保存します。設定 JSON やログ、コマンドライン引数には書きません。

通信は暗号化されますか？

標準の VNC は暗号化されません。信頼できる LAN か VPN で使ってください。TLS / VeNCrypt は未対応です。

画面が古い、残像が残るときは？

⌘R または操作バーの「再描画」で全体を描き直してください。

料金はかかりますか？

無料です。MIT License のオープンソースで、ソースコードも公開しています。
