WHY GLINTVNC

VNC 需要的，
是速度与安心。

画面卡顿、连接脆弱、设置复杂。GlintVNC 从减少这三个问题开始。

01

只画变化的部分

不重发整幅画面，只接收变化的矩形并分块上传到 GPU。拖动窗口时不容易出现拖影和迟滞。

02

坏数据也不会让应用崩溃

所有远端像素都按外部输入处理。检查尺寸、解压后大小和内存上限；服务器 15 秒无响应就断开。

03

日语和英语，完整到底

连接列表、配置文件、设置和会话工具栏全部本地化。密码只保存在 macOS 钥匙串。

WHAT IT DOES

每天的操作，
原样延伸到远端。

远程工作常用的功能，不必多绕一步。设置会随连接保存，下次从列表中选择即可。

查看连接方法 →
01同时连接多台主机
每个连接都有独立窗口，可以把两台 Mac 并排使用。
02全屏，更专注
F8 显示或隐藏控制栏，Esc 退出全屏。鼠标移到屏幕顶端即可唤出控制栏。
03合适的显示比例
适应窗口、1:1、拉伸按连接保存，键盘映射也可以按配置文件选择。
04复制粘贴，照常使用
文本剪贴板双向同步，可随时在设置中关闭。
05立即清除残影
画面看起来过期时，按 ⌘R 或点控制栏的“重绘”重画整个屏幕。
06密码安全保存
只保存在 macOS 钥匙串，不写入设置 JSON、日志或命令行参数。

连接

启动后选择“新建”，填入主机和密码即可。显示比例和键盘映射会保存在配置文件中。

  • 主机例如 192.168.1.20（也可用主机名）
  • 端口通常为 5900
  • 密码保存配置文件时存入 macOS 钥匙串

SAFETY

画面数据，
都是不可信输入。

VNC 服务器送来的像素和矩形不一定正确。GlintVNC 在解码前后检查尺寸和上限，让卡住的连接不会拖住整个应用。

  • ✓
    全程安全 Rust

    核心启用了 #![forbid(unsafe_code)]。

  • ✓
    边界检查

    Raw、CopyRect、ZRLE 解码器都会校验尺寸和目标区域。

  • ✓
    内存上限

    每次更新最多 128 MiB RGBA，画面最大 16 Mpx。

  • ✓
    可靠释放

    断开连接或失去焦点时，释放按下的键和鼠标按钮。

  • ✓
    仅钥匙串

    凭据不写入配置文件或日志。

标准 VNC 不加密通信。请勿直接暴露到互联网，应在可信 LAN 或 VPN 中使用。当前版本尚不支持 TLS / VeNCrypt 和 Apple ARD 认证。

FAQ

常见问题

安装前容易犹豫的几点，集中说明。

Apple Silicon 的 Mac 能用吗？

当前版本仅面向 Intel x86_64，尚未在 Apple Silicon 上验证。

密码保存在哪里？

只保存在 macOS 钥匙串，不写入设置 JSON、日志或命令行参数。

连接会加密吗？

标准 VNC 不加密。请在可信 LAN 或 VPN 中使用；暂不支持 TLS / VeNCrypt。

画面看起来旧、出现残影怎么办？

按 ⌘R 或点控制栏的“重绘”，重新绘制整个屏幕。

需要付费吗？

免费。采用 MIT License 开源，源代码已公开。
