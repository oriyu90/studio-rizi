GlintVNC

Safety-first Rust VNC viewer for Intel Mac

macOS 13+Rustv1.0.0JA/EN UI

GlintVNC is a native Rust VNC viewer built for the 2017 Intel MacBook Pro running macOS Ventura 13.7.8. It supports RFB 3.3 / 3.7 / 3.8 and VNCAuth, and safely decodes Raw, CopyRect and ZRLE encodings.

Safety-first design

Every byte from the remote server is treated as untrusted. The decoder checks dimensions, rectangles and decompressed sizes, caps per-update RGBA accumulation at 128 MiB and the framebuffer at 16 Mpx, and applies a 15-second read timeout so a stalled server cannot pin a worker or memory.

  • #![forbid(unsafe_code)] in the core; all safe Rust
  • Bounds-checked Raw / CopyRect / ZRLE decoding
  • Per-update memory budget and network read timeouts
  • Keys and buttons released on disconnect and focus loss
  • Passwords stored only in Keychain — never in JSON, logs or CLI args
  • Unencrypted transport allowed only by explicit profile opt-in

Compatibility and existing features

The RFB 3.3 / 3.7 / 3.8 handshake, VNCAuth, Raw / CopyRect / ZRLE encodings and the Cursor, DesktopSize and LED State pseudo-encodings are implemented, with x11vnc (LibVNCServer) and TigerVNC in mind. Dirty-rectangle streaming and partial GPU uploads keep drag updates small.

  • Dirty-rect streaming + TextureHandle::set_partial
  • 16 ms latest-wins pointer motion throttling
  • Spec-correct non-incremental request after DesktopSize
  • x11vnc LED State (0xFFFE0000) support
  • Refresh button / Cmd+R clears stale ghost pixels immediately
  • Not implemented: TLS/VeNCrypt, Tight/Hextile, Continuous Updates

Complete Japanese and English UI

The app UI is fully localized in Japanese and English. The connection list, profile editor, settings and in-session control bar all offer the same features in both languages. Display scale (Fit / 1:1 / Stretch) and keymap are configured per connection.

Download

Download the DMG from GitHub Releases. It is ad-hoc signed and not Apple-notarized. On first launch use right-click → Open, or allow it in System Settings → Privacy & Security. The signature changes on every rebuild, so Keychain may ask for approval again.
