WHY GLINTVNC

A VNC viewer needs
speed and calm.

Laggy screens, fragile connections, fiddly setup. GlintVNC started by shrinking all three.

01

Draw only what changed

Instead of resending the desktop, GlintVNC receives small dirty rectangles and uploads them in parts to the GPU. Dragging a window no longer feels like dragging the cursor with it.

02

Bad data will not take it down

Every remote pixel is treated as external input. Dimensions, decompressed sizes and memory ceilings are checked, and a stalled server is cut off after 15 seconds.

03

Japanese and English, all the way

The connection list, profiles, settings and session bar are fully localized. Passwords live only in the macOS Keychain.

WHAT IT DOES

Everyday work,
carried across.

The features remote work actually asks for, without extra steps. Settings stay with each connection, so next time you just pick it from the list.

See how to connect →
01Several hosts, side by side
Each connection gets its own window. Two Macs can sit next to each other while you work.
02Full screen, fewer distractions
F8 shows or hides the control bar, Esc leaves full screen. Move the pointer to the top edge to reveal the bar.
03A view that fits
Fit, 1:1 and Stretch are saved per connection, and the keymap is stored with the profile.
04Copy and paste, as usual
The text clipboard syncs both ways and can be turned off in Settings at any time.
05Clear stale pixels
⌘R or Refresh redraws the whole screen when the picture looks out of date.
06Passwords kept private
Stored only in the macOS Keychain, never in settings JSON, logs or command-line arguments.

SAFETY

Screen data is
untrusted input.

Pixels and rectangles arriving from a VNC server may be wrong. GlintVNC checks sizes and limits before and after decoding, so a stalled connection cannot freeze the whole app.

  • ✓
    Safe Rust throughout

    The core applies #![forbid(unsafe_code)].

  • ✓
    Checked boundaries

    The Raw, CopyRect and ZRLE decoders verify dimensions and destinations.

  • ✓
    Memory ceilings

    128 MiB of RGBA per update and a 16 Mpx framebuffer.

  • ✓
    Guaranteed release

    Pressed keys and mouse buttons are released on disconnect or focus loss.

  • ✓
    Keychain only

    Credentials are never written to settings files or logs.

Standard VNC does not encrypt traffic. Do not expose it directly to the internet; use a trusted LAN or VPN. TLS / VeNCrypt and Apple ARD authentication are not supported in this version.

  3. If macOS says the developer cannot be verified, allow it in System Settings → Privacy & Security → Open Anyway.

FAQ

Common questions

The points people usually wonder about before installing.

Does it run on Apple Silicon?

This version targets Intel x86_64 only. Apple Silicon has not been verified.

Where is the password stored?

Only in the macOS Keychain. It is not written to settings JSON, logs or command-line arguments.

Is the connection encrypted?

Standard VNC is not encrypted. Use a trusted LAN or VPN; TLS / VeNCrypt is not supported.

The picture looks old or leaves trails.

Press ⌘R or use Refresh in the control bar to redraw the whole screen.

Does it cost anything?

No. It is open source under the MIT License, with the source published on GitHub.
